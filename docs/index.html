About

BRIDGE (Brain Reconstruction Integrating Distributed Graph Estimates) is a distributed spatial graph framework for whole-brain structural connectivity, designed as an alternative to traditional tractography at terabyte scale.

It is developed principally for hierarchical phase-contrast X-ray tomography (HiP-CT) at the European Synchrotron, as part of the Human Organ Atlas and the CONNECTS Centre for Large-scale Imaging of Neural Circuits (LINC), but generalises to any high-resolution 3D brain volume.

Every reconstruction is written to a Zarr Vectors store: an open, chunked, cloud-native format for points, streamlines and graphs. Results can be read, queried and visualised with open-source tools, independently of BRIDGE itself.

Code availability. The BRIDGE source code is currently private ahead of publication. The data format and visualisation tools it is built on are open source and available now.

Builds probabilistic spatial graphs within each chunk, with CUDA kernels for edge scoring, pruning and path tracing.

Features

Built for scale and reproducibility

⚡

GPU Accelerated

Vertex extraction and graph construction run on GPU through CUDA kernels and the RAPIDS stack (CuPy, cuGraph, cuDF).

🧩

Chunked Processing

A divide-and-conquer approach handles volumes far larger than GPU memory, with fragments stitched across chunk boundaries.

📦

Zarr Vectors Native

Vertices, edges, fragments and chains live in one chunked, spatially indexed Zarr v3 store that other tools can open directly.

🔭

Multiscale

Couples reconstructions of the same specimen imaged at different resolutions, from whole-organ overviews to local zooms.

📊

BIDS Structured

Outputs are organised as BIDS derivative datasets built on OME-Zarr, and export to streamlines, adjacency matrices and GraphML.

🔬

Synchrotron Ready

Designed for HiP-CT, the Human Organ Atlas and CONNECTS-scale microscopy initiatives worldwide.

Zarr Vectors

An open storage format for large-scale vector geometry

Most Zarr data is a dense array, where the index into the array is the position in space. Zarr Vectors instead stores entities by their coordinates: point clouds, streamlines, graphs, skeletons and meshes. Stores are chunked in space, carry multiresolution pyramids and use OME-Zarr-compatible metadata.

The specification was originally drafted by Forrest Collman at the Allen Institute. The BRIDGE team co-develops its Python implementation and tooling with the Allen Institute, driven by the needs of whole-brain fibre reconstruction.

BRIDGE writes each reconstruction to a graph.zarrvectors store inside the acquisition's OME-Zarr container. Anyone with the open tools below can load a region of a whole-brain network by bounding box, follow chains across chunks, or view it in Neuroglancer, without needing BRIDGE.

  • Specification → The format itself: store layout, geometry types and multiscale levels.
  • zarr-vectors-py → Python API for reading, writing and spatially querying stores.
  • zarr-vectors-tools → Conversions (TRK, TRX, TCK, SWC, meshes…), graph algorithms and the zvtools CLI.
