About

BRIDGE (Brain Reconstruction Integrating Distributed Graph Estimates) is a framework for whole-brain structural connectivity in terabyte-scale imaging.

It is developed principally for hierarchical phase-contrast X-ray tomography (HiP-CT) at the European Synchrotron, as part of the Human Organ Atlas and the CONNECTS Centre for Large-scale Imaging of Neural Circuits (LINC), but generalises to any high-resolution 3D brain volume.

Results are written to a Zarr Vectors store: an open, chunked, cloud-native format for points, streamlines and graphs. Results can be read, queried and visualised with open-source tools, independently of BRIDGE itself.

Code availability. The BRIDGE source code is currently private ahead of publication. The data format and visualisation tools it is built on are open source and available now.

Zarr Vectors

An open storage format for large-scale vector geometry

Most Zarr data is a dense array, where the index into the array is the position in space. Zarr Vectors instead stores entities by their coordinates: point clouds, streamlines, graphs, skeletons and meshes. Stores are chunked in space, carry multiresolution pyramids and use OME-Zarr-compatible metadata.

The specification was originally drafted by Forrest Collman at the Allen Institute. The BRIDGE team co-develops its Python implementation and tooling with the Allen Institute.

BRIDGE writes its results as Zarr Vectors, so anyone with the open tools below can read and view them without BRIDGE.

  • Specification → The format itself: store layout, geometry types and multiscale levels.
  • zarr-vectors-py → Python API for reading, writing and spatially querying stores.
  • zarr-vectors-tools → Conversions (TRK, TRX, TCK, SWC, meshes…), graph algorithms and the zvtools CLI.

Projects

Open-source tools for connectomics research

zarr-vectors-py

Python · with the Allen Institute

Reference Python implementation of the Zarr Vectors format.

  • Points, streamlines, graphs, skeletons and meshes
  • Bounding-box and per-object reads
  • Multiresolution pyramids with object sparsity
  • Zarr v3 with sharding and OME-Zarr metadata
Repository → Docs →

zarr-vectors-tools

Python · with the Allen Institute

Workflows, algorithms and multiresolution built on zarr-vectors-py.

  • Ingest and export for common tractography and mesh formats
  • Streaming graph and mesh algorithms
  • Coarsening for multiresolution pyramids
  • zvtools command-line interface
Repository → Docs →

Neuroglancer + Zarr Vectors

TypeScript · fork of google/neuroglancer

Browser viewing of Zarr Vectors stores next to the image volumes they came from.

  • Zarr Vectors data source
  • Streamlines, point clouds and graphs
  • Level-of-detail loading from pyramids
  • Companion Python tooling in zv-ngtools
